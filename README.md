# josediaztutoring.com

One-page site in English (`/`) and Spanish (`/es/`) on Google App Engine
standard. The pages are static files; the only code is `server.js` (Node.js),
which receives the booking form (`POST /api/contact`) and sends two emails
through an SMTP server, Gmail by default (the request to Jose, Reply-To = the client, and a fixed
confirmation to the client), plus a few redirects and the 404 page.

```
app.yaml          App Engine config (handlers, caching, security headers, scaling)
server.js         booking form, redirects and 404 page (Node.js, no framework)
package.json      Node dependencies (just nodemailer) and npm scripts
package-lock.json
.gcloudignore     uploads only app.yaml, server.js, package files and www/
i18n/es.js        Spanish text for /es/ (one entry per data-i18n key)       <- edit
scripts/
  build.js        builds www/es/index.html, the JSON-LD and sitemap.xml
  dev-server.js   local preview that follows app.yaml (email stubbed)
  smoke-test.js   local checks (npm test)
www/
  index.html      English page: HTML, CSS, JS, CONFIG, photo (base64)    <- edit
  es/index.html   Spanish page: GENERATED by `npm run build`, don't edit
  404.html        bilingual "page not found" (served by server.js)
  llms.txt        plain-language summary for AI assistants (hand-written)
  og-image.png    1200x630 link-preview image (WhatsApp, Facebook, LinkedIn)
  favicon.ico, favicon.svg, apple-touch-icon.png
  robots.txt
  sitemap.xml     GENERATED by `npm run build`
```

## Editing the site

**Edit `www/index.html` (English) + `i18n/es.js` (Spanish), run the build, deploy.**

1. Edit `www/index.html` and/or `i18n/es.js`. A new piece of text needs a
   `data-i18n="key"` attribute in the HTML and the same key in `i18n/es.js`
   (placeholders use `data-i18n-ph`, other attributes `data-i18n-attr="aria-label:key"`).
2. Build. This regenerates `www/es/index.html`, the structured data (JSON-LD) in
   both pages and `sitemap.xml`, and stops with an error if a Spanish entry is missing:

   ```bash
   npm run build
   ```

   The build runs on your machine, not on App Engine: `"gcp-build": ""` in
   `package.json` stops App Engine from running `npm run build` during deploy
   (`scripts/` isn't uploaded). Don't remove it.
3. Check locally (optional): `npm test` runs the checks; `npm run dev` serves the
   site at http://localhost:8080 the way App Engine does, with email stubbed.
4. Update `www/llms.txt` by hand if you changed rates, subjects or credentials.
5. Deploy (always check the project first; it must be `jalex-hub`):

   ```bash
   gcloud config get-value project
   ```

   ```bash
   gcloud app deploy app.yaml --project=jalex-hub
   ```

The homepage is cached for 10 minutes, so changes show up within ~10 min
(hard-refresh to see them sooner). `og-image.png` is cached for 7 days; if you
replace it, rename it (e.g. `og-image-2.png`) and update the three meta tags
and the handler in `app.yaml`, or WhatsApp/Facebook will keep the old one.

## CONFIG

Near the bottom of `www/index.html`, inside the `<script>` block: WhatsApp,
phone, LinkedIn, public email, Google Business Profile URL, Google review link,
engineering degree field and `testimonials`. A value still in `[brackets]` is
treated as not set: its footer link stays hidden and it is left out of the
structured data. `testimonials: []` keeps the testimonials section hidden; add
real quotes (`{ quote, name, detail, result }`) to show it. After any change
here, run `npm run build` so `/es/` and the structured data pick it up.

The phone number in the footer is plain HTML (search for `tel:`); keep it in
sync with `CONFIG.phone`.

The form's on-page messages (sending / sent / failed) are in `FORM_MSG` just
below CONFIG.

## Booking form (email)

Mail goes out through any SMTP server. **Which server** is set in `app.yaml`
under `env_variables` (not secret); **the login** is in Secret Manager, never in
this repo. The defaults are Gmail with an App Password.

`app.yaml` → `env_variables`:

| Variable | Default | Meaning |
|---|---|---|
| `SMTP_HOST` | `smtp.gmail.com` | SMTP server |
| `SMTP_PORT` | `465` | `465` (implicit TLS) or `587` (STARTTLS) |
| `SMTP_SECURE` | `true` on 465, else `false` | `false` = STARTTLS; TLS is still required, the password is never sent in clear text |
| `MAIL_DAILY_LIMIT` | `40` | form submissions per day in total (each sends 2 emails); keep it under your provider's limit |

Secret Manager (project `jalex-hub`):

| Secret | Value |
|---|---|
| `smtp-user` | the SMTP login (for Gmail: the address that sends the mail) |
| `smtp-password` | the SMTP password, App Password or API key |
| `smtp-from` | optional: the From address, when the login isn't an email address (e.g. SendGrid's `apikey`, Amazon SES keys); default `smtp-user` |
| `owner-email` | optional: send requests to this address; default the From address |

The From address must be one the provider lets you send as (a verified
sender/domain), or mail will be rejected or land in spam.

Common providers:

| Provider | `SMTP_HOST` | `SMTP_PORT` | `smtp-user` | `smtp-password` |
|---|---|---|---|---|
| Gmail / Google Workspace | `smtp.gmail.com` | `465` | the address | App Password |
| Microsoft 365 / Outlook | `smtp.office365.com` | `587` | the address | account password (SMTP AUTH must be enabled for the mailbox) |
| Zoho Mail | `smtp.zoho.com` | `465` | the address | app-specific password |
| SendGrid | `smtp.sendgrid.net` | `465` | `apikey` | API key (+ `smtp-from`) |
| Mailgun | `smtp.mailgun.org` | `587` | SMTP login from Mailgun | its SMTP password |
| Amazon SES | `email-smtp.<region>.amazonaws.com` | `465` | SMTP username | SMTP password (+ `smtp-from`) |

Switch provider: edit `env_variables` in `app.yaml`, then set the secrets
(`gcloud secrets create NAME --data-file=- --project=jalex-hub` for a new one,
`versions add` for an existing one), then deploy:

```bash
printf '%s' 'LOGIN' | gcloud secrets versions add smtp-user --data-file=- --project=jalex-hub
printf '%s' 'PASSWORD-OR-KEY' | gcloud secrets versions add smtp-password --data-file=- --project=jalex-hub
printf '%s' 'hello@josediaztutoring.com' | gcloud secrets create smtp-from --data-file=- --project=jalex-hub
gcloud secrets add-iam-policy-binding smtp-from --project=jalex-hub \
  --member=serviceAccount:jalex-hub@appspot.gserviceaccount.com --role=roles/secretmanager.secretAccessor
gcloud app deploy app.yaml --project=jalex-hub
```

(The IAM binding is only needed for a new secret if access is granted per
secret rather than project-wide.) After only changing a secret's value,
redeploy or wait for the instance to restart, since secrets are cached in memory.
On startup the log shows `Listening on 8080 (SMTP host:port, TLS|STARTTLS)`.

Abuse protection: a hidden honeypot field, max 3 requests per visitor per hour
and `MAIL_DAILY_LIMIT` (40) per day in total, and the client confirmation never repeats the free-text
message (so the form can't be used to send arbitrary text to someone).
Delivery failures are in Logs Explorer (search "Failed to send booking email").

Edit the email wording in `CONFIRM` and `LABELS` in `server.js`.

## Caching and headers

| Path | Cache | Notes |
|---|---|---|
| `/`, `/es/` | 10 min | static |
| `/og-image.png`, favicons | 7 days | static |
| `/robots.txt`, `/sitemap.xml`, `/llms.txt` | 10 min | static |
| `/index.html`, `/es`, `/es/index.html` | 1 hour | `server.js`: 301 to `/` or `/es/` |
| `/?lang=es` | — | the static `/` can't see query strings; a script at the top of `index.html` sends it to `/es/` |
| `/api/*` | never | `server.js` (unknown `/api/*` paths get a JSON 404) |
| anything else | 10 min | `server.js`: 404 with `www/404.html`, `X-Robots-Tag: noindex` |

Every handler: `secure: always` (HTTP → 301 to HTTPS), `Strict-Transport-Security`,
`X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`.
There is deliberately **no Content-Security-Policy**: the page uses inline
`<script>`/`<style>` and Google Fonts, and a strict CSP would break the language
toggle, the form and the WhatsApp button.
