# josediaztutoring.com

One-page site in English (`/`) and Spanish (`/es/`), plus three legal pages in
both languages (`/privacy/`, `/terms/`, `/accessibility/` and
`/es/privacidad/`, `/es/terminos/`, `/es/accesibilidad/`), on Google App Engine
standard. The pages are static files; the only code is `server.js` (Node.js),
which receives the booking form (`POST /api/contact`) and sends two emails
through an SMTP server, Gmail by default (the request to Jose, Reply-To = the client, and a fixed
confirmation to the client), plus a few redirects and the 404 page.

## Editing the site

**Edit `www/index.html` (English) + `i18n/es.js` (Spanish), run the build, deploy.**

1. Edit `www/index.html` and/or `i18n/es.js`. A new piece of text needs a
   `data-i18n="key"` attribute in the HTML and the same key in `i18n/es.js`
   (placeholders use `data-i18n-ph`, other attributes `data-i18n-attr="aria-label:key"`).
2. Build. This regenerates `www/es/index.html`, the structured data (JSON-LD) in
   both pages and `sitemap.xml`, and stops with an error if a Spanish entry is missing:

   ```bash
   npm run build
   ```

   The build runs on your machine, not on App Engine: `"gcp-build": ""` in
   `package.json` stops App Engine from running `npm run build` during deploy
   (`scripts/` isn't uploaded). Don't remove it.
3. Check locally (optional): `npm test` runs the checks; `npm run dev` serves the
   site at http://localhost:8080 the way App Engine does, with email stubbed.
4. Update `www/llms.txt` by hand if you changed subjects or credentials (its price lines come from `pricing.js`).
5. Deploy (always check the project first; it must be `jalex-hub`):

   ```bash
   gcloud config get-value project
   ```

   ```bash
   gcloud app deploy app.yaml --project=jalex-hub
   ```

6. Confirm the new version has 100% of traffic (`TRAFFIC_SPLIT` 1.00):

   ```bash
   gcloud app versions list --project=jalex-hub --service=default --sort-by=~version.createTime --limit=3
   ```

7. Tell search engines what changed (IndexNow: Bing, Yandex, Seznam, Naver, Yep,
   Internet Archive, Amazon), then commit the updated state:

   ```bash
   npm run indexnow
   git add seo/published-pages.json www/sitemap.xml && git commit -m "IndexNow: record published pages"
   ```

   **Always commit `seo/published-pages.json` after `npm run indexnow`**: the build
   reads every date from it, so without it a fresh clone can't tell old pages from
   changed ones.

   The build hashes each page's own content (SHA-256 of its `<title>`, meta
   description and `<main>`, without scripts, the shared WhatsApp button and motto
   band, the "Last updated" date and the © year; never the `<head>`, GTM, header,
   footer or shared CSS) and compares it with `seo/published-pages.json`. A page that
   matches keeps its date. A page that differs is listed in
   `seo/pending-indexnow.json` and dated from git: today if its source files
   (`pages/*.html`, `pages/exams/*.html`, `www/index.html`, plus `i18n/es.js` for the
   Spanish pages) have an uncommitted content change, else the date of the last
   commit that changed its content. The build stops in a shallow clone when it needs
   that history (`git fetch --unshallow`). The exam pages' date is the later of that
   and the date of the bundled exam data's current revision (its `changelog`).
   The sitemap `lastmod` and the legal pages' "Last updated" are the same date.
   `npm run build -- --from-history` re-derives every date from git and rewrites
   `seo/published-pages.json` (only when the current pages are live).
   `npm run indexnow` checks that the live key file matches, submits just the
   pending URLs, and on HTTP 200/202 records them in `seo/published-pages.json`. If nothing changed it says
   "IndexNow: nothing changed". On any error (400 bad request, 403 key not valid,
   422 URL/key mismatch, 429 too many requests, network) it prints the reason, keeps
   the pending list for the next run and still exits 0, so it never breaks a deploy.
   It never retries in a loop.

   - `npm run indexnow -- --dry-run` prints the payload and sends nothing.
   - `npm run indexnow -- --urls / /es/` submits exactly those paths, for a change
     that doesn't alter the built HTML (e.g. a rate kept outside the page).

The homepage is cached for 10 minutes, so changes show up within ~10 min
(hard-refresh to see them sooner). `og-image.png` is cached for 7 days; if you
replace it, rename it (e.g. `og-image-2.png`) and update the three meta tags
and the handler in `app.yaml`, or WhatsApp/Facebook will keep the old one.

## Legal pages

Privacy Policy, Terms of Service and Accessibility Statement. The English text is
in `pages/*.html`, the Spanish text in `i18n/es.js` (keys `pp*`, `tos*`, `acc*`;
each section is one entry). The build wraps them in the site's real header,
footer, `<head>` (GTM included) and CSS, both taken from `www/index.html`, and
writes the table of contents as static HTML. Change both languages together.

- **"Last updated" / "Last reviewed"** is the date (America/New_York) the page's own
  text last changed: the same date as its sitemap `lastmod` (see step 7 above). Header,
  footer, GTM or CSS changes don't move it.
  The sitemap `lastmod` dates and the footer © year use the same time zone.
- The build stops if a legal page has leftover `[placeholder]` text, if the
  Terms page has a price, amount or package size (rates live only on the home
  page), if the Privacy or Terms page has a phone number (email only there), if
  an in-page link points nowhere, or if a meta description is over 155 characters.
- The footer (Policies links, © year, "independent service" line) is part of
  `www/index.html`; the build copies it to every page, including `www/404.html`.

## Booking form (email)

Mail goes out through any SMTP server (Gmail with an App Password by default).
All mail settings are secrets in Secret Manager (project `jalex-hub`), never in
this repo. The server re-reads them every 5 minutes, so **changing a secret
takes effect within ~5 minutes, no redeploy needed.**

The mail server is one JSON secret, `smtp-config`:

```json
{
  "user": "jose@example.com",
  "password": "your-app-password",
  "host": "smtp.gmail.com",
  "port": 465,
  "secure": true,
  "from": "Jose Diaz Tutoring <jose@example.com>",
  "ownerEmail": "jose@example.com"
}
```

| Key | Required | Default | Value |
|---|---|---|---|
| `user` | yes | | the SMTP login (for Gmail: the address that sends the mail) |
| `password` | yes | | the SMTP password, App Password or API key |
| `host` | no | `smtp.gmail.com` | SMTP server |
| `port` | no | `465` | `465` (implicit TLS) or `587` (STARTTLS) |
| `secure` | no | `true` on 465, else `false` | `false` = STARTTLS; TLS is still required, the password is never sent in clear text |
| `from` | no (yes if `user` isn't an email) | `user` | the From address, when the login isn't an email address (SendGrid's `apikey`, Amazon SES keys) |
| `ownerEmail` | no | the From address | where requests are sent |

Leave an optional key out to use its default. Any other key is rejected, so a
typo (`"Host"`) fails loudly instead of being ignored.

The booking limits are separate secrets (plain numbers):

| Secret | Required | Default | Value |
|---|---|---|---|
| `mail-ip-hourly-limit` | no | `20` | form submissions per IP address per hour (a school or university shares one IP) |
| `mail-email-hourly-limit` | no | `3` | form submissions per client email address per hour |
| `mail-daily-limit` | no | `40` | form submissions per day in total (2 emails each); keep it under your provider's limit |

`from` and `ownerEmail` take a bare address (`jose@example.com`) or a
name and address (`Jose Diaz Tutoring <jose@example.com>`); without a name the
mail shows "Jose Diaz Tutoring". The From address must be one the provider lets you send as (a verified
sender/domain), or mail will be rejected or land in spam.

Common providers:

| Provider | `host` | `port` | `user` | `password` |
|---|---|---|---|---|
| Gmail / Google Workspace | `smtp.gmail.com` | `465` | the address | App Password |
| Microsoft 365 / Outlook | `smtp.office365.com` | `587` | the address | account password (SMTP AUTH must be enabled for the mailbox) |
| Zoho Mail | `smtp.zoho.com` | `465` | the address | app-specific password |
| SendGrid | `smtp.sendgrid.net` | `465` | `apikey` | API key (+ `from`) |
| Mailgun | `smtp.mailgun.org` | `587` | SMTP login from Mailgun | its SMTP password |
| Amazon SES | `email-smtp.<region>.amazonaws.com` | `465` | SMTP username | SMTP password (+ `from`) |

Create the secret (once) from a local file, let the app read it, then delete the file:

```bash
gcloud secrets create smtp-config --data-file=smtp-config.json --replication-policy=automatic --project=jalex-hub
gcloud secrets add-iam-policy-binding smtp-config --project=jalex-hub \
  --member=serviceAccount:jalex-hub@appspot.gserviceaccount.com --role=roles/secretmanager.secretAccessor
rm smtp-config.json
```

Change it (e.g. a new App Password): add a new version with the **whole** JSON,
since each version replaces the previous one entirely:

```bash
gcloud secrets versions add smtp-config --data-file=smtp-config.json --project=jalex-hub
```

See the current value: `gcloud secrets versions access latest --secret=smtp-config --project=jalex-hub`.

**Mail still goes through Gmail after changing settings?** Check the logs (Logs
Explorer): on startup and on every send the app logs `SMTP server:` /
`Sending via host:port`. A `secret smtp-config: HTTP 403` error means the app
may not read the secret: run the `add-iam-policy-binding` command above. No such
lines at all means the running version predates these settings: deploy again.

A missing `smtp-config`, invalid JSON, a missing `user`/`password` or an invalid
value (e.g. `"port": "abc"`) makes sending fail with a clear message in the
logs; if a refresh from Secret Manager fails, the last good value keeps being used.

Abuse protection: a hidden honeypot field, and per hour at most
`mail-ip-hourly-limit` (20) requests per IP address and `mail-email-hourly-limit`
(3) per client email, plus `mail-daily-limit` (40) per day in total. The IP limit
is generous because a school or university network shares one IP; the per-email
limit stops anyone from flooding one inbox with confirmations. The client
confirmation never repeats the free-text message (so the form can't be used to
send arbitrary text to someone). The counters are in memory and reset on a
restart or redeploy.

Edit the email wording in `CONFIRM` and `LABELS` in `server.js`. The client
confirmation ends with a short footer (business, service area, why they got it,
links to the Privacy Policy and Terms) in the visitor's language.

## Prices

Every price on `/`, `/es/` and `/llms.txt` comes from one JSON secret,
`site-pricing` (project `jalex-hub`). **Changing it needs no rebuild and no
redeploy**: the server re-reads it every 10 minutes and the pages are cached
10 minutes in browsers, so everyone sees a change within ~20 minutes.

```json
{
  "currency": "USD",
  "rates": { "highSchool": 65, "college": 90, "engineering": 110, "groupPerStudent": 40 },
  "plans": [
    { "id": "hs-monthly", "level": "highSchool", "sessions": 8, "price": 429, "period": "month" },
    { "id": "college-semester", "level": "college", "sessions": 12, "price": 899, "period": "semester" },
    { "id": "engineering-semester", "level": "engineering", "sessions": 12, "price": 1099, "period": "semester" }
  ]
}
```

Change prices (validates first, refuses an invalid file, then pings IndexNow):

```bash
scripts/set-pricing.sh pricing.json
```

- Whole dollars only; the three plan ids, levels and periods are fixed (the page
  has a row for each); a plan must cost less than its sessions at the single rate.
  Unknown keys (e.g. `from`) are rejected. Check a file without sending it:
  `node pricing.js pricing.json` (prints what the page will show).
- Derived, never typed: per hour = price / sessions ("about $N/hour" unless whole),
  save = sessions × rate − price, badge = rounded average plan saving %, JSON-LD
  `priceRange` = lowest–highest rate. All in `pricing.js`.
- If the secret is missing or invalid, the server uses the built-in fallback
  (`pricing.js` → `FALLBACK`) and logs `Pricing: ...` warnings. The built HTML
  always holds the fallback values, so the page is right even if filling fails.
  **Keep `FALLBACK` equal to the live secret** (edit it, `npm run build`, deploy)
  when a price change is meant to last.
- In the HTML, prices are `<span data-price="...">` (see `pricing.js`); never
  type a `$` amount in the rates section (`npm test` checks).
- Try prices locally: `PRICING_FILE=pricing.json npm run dev`.

Create the secret (once) and let the app read it:

```bash
gcloud secrets create site-pricing --data-file=pricing.json --replication-policy=automatic --project=jalex-hub
gcloud secrets add-iam-policy-binding site-pricing --project=jalex-hub \
  --member=serviceAccount:jalex-hub@appspot.gserviceaccount.com --role=roles/secretmanager.secretAccessor
```

## Resources (free interactive tools)

Upload one AI-generated HTML tool in the admin
(`https://admin-dot-jalex-hub.ue.r.appspot.com`, Google sign-in via IAP), write the EN/ES text, tick
"I checked the formulas and the Spanish", Publish. Within ~30 seconds it's live at
`/resources/<slug>/` and `/es/recursos/<slug>/`, in the library, on the home page (3 newest) and in the
sitemap. **No deploy.** Setup: `docs/resources-setup.md`. What to ask the AI for:
`docs/resources-tool-guide.md`.

- Data: Firestore (`resources` collection, `meta/resources` change marker) + the private bucket
  `josediaz-tutoring-res` (`resources/<id>/v<N>.html`, `og/<id>-<lang>-<hash>.png`). `resources.js` re-checks
  the marker at most every 15 s and keeps the last good data if Firestore is down.
- Isolation: the tool is served at `/frame/<id>/v<N>` with `Content-Security-Policy: sandbox …` (never
  `allow-same-origin`) and `frame-ancestors 'self'`, and loaded in an `<iframe sandbox>`. It can't read
  cookies, the page or the admin, even when opened directly. A small injected script keeps
  `localStorage`/cookies from crashing tools and mirrors the tool's `#hash` into the page URL (Copy link).
- URLs: changing a slug after publishing keeps a 301 from the old one; Unpublish gives 410; drafts 404.
  Slugs `og` and `katex` are reserved.
- The page text is in Firestore, edited in the admin; the bar's and the page's fixed labels are in
  `lib/resources/render.js` (`T`). Preview cards are made on publish (`admin/cards.js`, satori + resvg,
  fonts in `admin/fonts/`, SIL OFL).
- Local: `npm install --prefix admin`, then `npm run dev` and `npm run admin:dev` (shared folder
  `.dev-data/resources`, no sign-in).
- Deploy the admin with `gcloud app deploy admin/admin.yaml --project=jalex-hub` after `npm run build`.

## Analytics (Google Tag Manager)

Every page (`/`, `/es/`, the legal pages, the 404 page) loads Google Tag Manager container
`GTM-TG7DX6ZB`: the official snippet sits high in `<head>` and its `<noscript>`
iframe right after `<body>`. To change the container, replace the ID in
`www/index.html` and `www/404.html`, then `npm run build`.

The page pushes these events to the `dataLayer` (no names, emails or messages):

| Event | When | Parameters |
|---|---|---|
| `generate_lead` | booking form sent successfully | `form_name`, `student_level`, `page_language` |
| `contact_click` | WhatsApp, phone or email link clicked | `contact_method`, `link_location`, `page_language` |
| `resource_link_copy` | Copy link on a tool page | `resource_id`, `has_state`, `page_language` |
| `resource_fullscreen` | Full screen on a tool page | `resource_id`, `page_language` |
| `resource_book_click` | "Book a free intro" on a tool page (bar or bottom) | `resource_id`, `link_location` (`bar`/`cta`), `page_language` |

In Tag Manager: add a **Google tag** with your GA4 measurement ID (`G-…`) on
*Initialization – All Pages*, then a **GA4 Event** tag per event above (trigger:
*Custom Event* with that name, event parameters from *Data Layer Variables*).
Mark `generate_lead` as a key event in GA4. Preview mode shows the events firing.

## Caching and headers

| Path | Cache | Notes |
|---|---|---|
| `/` | private, revalidated every visit (`Vary: Cookie`) | `server.js`; with the cookie `lang=es` it 302s to `/es/` (query string kept, the redirect is never cached) |
| `/es/` | private, 10 min | `server.js` (prices filled in) |
| `/exams/` | private, revalidated every visit (`Vary: Cookie`) | `server.js`; with `lang=es` it 302s to `/es/examenes/`. The other exam pages: 10 min |
| `/privacy/`, `/terms/`, `/accessibility/`, `/es/privacidad/`, `/es/terminos/`, `/es/accesibilidad/` | private, 10 min | `server.js` (built files; not static, so they can re-send the `lang` cookie) |
| the same without the trailing slash, or as `/privacy.html` | 1 hour | `server.js`: 301 to the slash URL |
| `/og-image.png`, favicons | 7 days | static |
| `/robots.txt` | 10 min | static |
| `/sitemap.xml` | 10 min | `server.js` (`resources.js`): the built file + the library and published tools |
| `/resources/`, `/es/recursos/`, `/resources/<slug>/` | private, 30 s (`/resources/` revalidated, `Vary: Cookie`) | `resources.js`; `/resources/` with `lang=es` 302s to `/es/recursos/` |
| `/frame/<id>/v<N>`, `/resources/og/*.png`, `/resources/katex/*` | 1 year, immutable | `resources.js` (the version or a hash is in the URL) |
| `/llms.txt`, `/exams/data.json` | 10 min, public | `server.js` |
| `/index.html`, `/es`, `/es/index.html` | 1 hour | `server.js`: 301 to `/` or `/es/` |
| `/?lang=es` | 1 hour | `server.js`: 301 to `/es/` (keeps `?topic=`); the script at the top of `index.html` does the same as a fallback |
| `/api/*` | never | `server.js` (unknown `/api/*` paths get a JSON 404) |
| anything else | 10 min | `server.js`: 404 with `www/404.html`, `X-Robots-Tag: noindex` |

**Language preference.** The EN/ES toggle (the `lang-switch` script in `www/index.html`, copied
into the legal and exam pages by the build) saves the cookie `lang=en|es` (1 year, `Secure`,
`SameSite=Lax`) only when it's clicked, and sends the visitor to the same section on the other
page (`data-twin-id` maps the legal pages' headings, whose ids differ by language). Only `/` and
`/exams/` act on the cookie; the privacy policy's cookie section describes it. Every HTML page (all
served by `server.js`, all `Cache-Control: private`) re-sends a valid `lang` cookie as a server-set
cookie, because Safari deletes cookies set by JavaScript after 7 days; a request without the cookie
never gets one. The same script shows a language suggestion bar (no cookie yet, and the browser's
first `en`/`es` language isn't the page's): accept = `switchLanguage()`, close or Esc = `lang` set to
the page's language. Only the script builds it, so crawlers and no-JS visitors never see it.

Every handler: `secure: always` (HTTP → 301 to HTTPS), `Strict-Transport-Security`,
`X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`.
There is deliberately **no Content-Security-Policy**: the page uses inline
`<script>`/`<style>` and Google Fonts, and a strict CSP would break the language
toggle, the form and the WhatsApp button.
